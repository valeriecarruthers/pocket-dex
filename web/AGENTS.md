# Pocket Dex web app

The web half of a two-platform product. The SwiftUI original is at the repo root;
`.claude/skills/port-ios-feature/SKILL.md` covers how to keep the two aligned.

## Things that will bite you

**There is no runtime data layer.** Every page renders from `src/data/`, generated
at build time by `scripts/build-dataset.mjs`. If a feature needs data that is not
in the dataset, extend the generator and regenerate — do not add a client-side
`fetch`. That would reintroduce exactly the runtime fragility the static dataset
exists to avoid.

**The type chart is hand-written and load-bearing.** `src/lib/pokemon-type.ts`
states all 324 matchups from the attacker's side and derives the defensive view.
`npm test` checks it against PokeAPI's own damage relations. If you touch it, run
the test.

**Per-species detail is read from disk, not imported.** `src/lib/dataset.ts` uses
`fs.readFile` for `src/data/species/<id>.json` deliberately, so 1,025 files never
land in a bundle. Importing them directly would work and would quietly bloat the
build.

**Notable Next 16 specifics used here:** `params` is a Promise and must be
awaited; `PageProps<'/route'>` is generated by `npx next typegen`; Turbopack is
the default for both dev and build.

## Verifying

```bash
npm run build   # prerenders 1,049 pages
npm test        # type chart vs upstream
npm run screenshot   # real browser, both themes, both viewports
```

A green build says the types line up and pages prerendered. It says nothing about
whether the page looks right — use the `visual-qa` skill for that.
